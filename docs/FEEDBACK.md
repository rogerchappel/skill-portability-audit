# Pre-1.0 user feedback plan

This plan tracks external feedback needed before the 1.0 release. The project is local-first and does not collect telemetry; feedback is voluntary and should be shared through a public GitHub issue in this repository. Do not include private skill contents, credentials, or other sensitive material in reports.

## Questions for users

1. Which skill formats and repository layouts did you try, and what environment (OS and Node.js version) did you use?
2. Did installation and the documented CLI/library examples work as written? If not, what command failed and what output did you see (with sensitive paths/content removed)?
3. Which portability or approval finding was most useful, and which finding was incorrect or missing?
4. Were the severity and explanation clear enough to decide what to change?
5. What important workflow or portability case should be addressed before 1.0?
6. Would you use the tool again, and what would prevent adoption?

## Collection and review process

1. Invite users to open an issue using the **User feedback (pre-1.0)** title prefix; ask them to answer the questions above and include the tool version and sanitized reproduction details.
2. Record each response below as an issue link, date, and concise finding. Ask permission before quoting feedback outside its original issue; do not copy sensitive content.
3. Triage each item as `action`, `consider`, or `not planned`, with a short rationale and (when actionable) a linked follow-up issue.
4. Before 1.0, review all recorded responses, resolve or explicitly defer actionable items, and update this document with the review date and decision summary.
